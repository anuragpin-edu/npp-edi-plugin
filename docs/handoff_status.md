## 3. Next Steps (The Plan)
When you resume work, follow this sequence:

### Step 1: Perform the Manual Acceptance Test
Download the `NppEdiLexer-PoC-x64` artifact from GitHub Actions (Run ID `30716025006`).
1. Extract `NppEdiLexer.dll` to `C:\Program Files\Notepad++\plugins\NppEdiLexer\`.
2. Extract `NppEdiLexer.xml` to your Notepad++ Config directory (`%APPDATA%\Notepad++\` or `plugins\Config\`).
3. Start Notepad++.
4. Verify the plugin loads without the ANSI error.
5. Check **Plugins -> NppEdiLexer -> About NppEdiLexer** (should not crash).
6. Check **Language -> EDI** and confirm that `EDI X12`, `EDI EDIFACT`, and `EDI VDA` are visible and selectable.

### Step 2: Implement PoC-B (Structural Lexing)
Once PoC-A is manually verified, proceed to **PoC-B**, which involves writing the actual structural C++ lexer logic in Lexilla.

- For **EDIFACT**: Locate the `UNA` segment (if present) to dynamically identify the component, element, decimal, release, and segment terminators. If absent, fallback to default `+`, `:`, `?`, `'`.
- For **X12**: Locate the `ISA` segment to extract the element separator, component separator, and segment terminator.
- Use `pAccess->StyleAt` and `pAccess->SetStyles` to safely map structural tokens to the 7 defined `LexerStyles`.

### Step 3: Semantic Layer Architecture (L1 / L6)
After PoC-B is green, the C# managed plugin will take over semantic models, dictionary metadata, and hover tips by referencing the UTF-16 spans generated by the C++ structural foundation.
